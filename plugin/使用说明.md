# 语音插件 · 使用说明（一页版）

> 给 **agent（小肥鱼）** 看的一页操作手册：拿到手照这个走，就能发语音消息、打语音通话。
> 原理与历史在 `NOTES.md`，接口细节在 `README.md`，这里只讲**怎么做、不能怎么做**。
> 版本 v0.6.0 · 2026-11-05

## 0. 开工前：先记住这五件事

| # | 事实 | 意味着 |
| --- | --- | --- |
| 1 | **两种模式，信号不同** | 看到 `【语音 N.Ns】http…` ＝ **单条语音消息**；看到 `（语音通话已开始）` ＝ **通话**。两者规则不通用，看到哪个走哪套。 |
| 2 | **服务要活着** | TTS 在 18082、ASR 在 18080。`voice_say` 会自己把 TTS 拉起来，拉不起来就直接报错，不会静默。 |
| 3 | **我不"听"音频，我读文本** | 用户说的话由客户端转成文字；通话内容进本会话的 `…\输出\calls\<sessionId>\voice-inbox.jsonl`，路径工具会回给我。 |
| 4 | **半双工** | 我播报时**麦克风是关的**，用户这时说的话会丢或排队。用户要插话，只能点悬浮条上的「打断」。 |
| 5 | **一条 ≤120 字（约 30 秒）** | 更长的内容拆成多条，但必须**连着发完**（见 B⑤），不要中间停顿。 |

## A. 单条语音消息（回合制）

### 怎么做

| 步 | 动作 | 验收 |
| --- | --- | --- |
| A0 | **先应一句（要动手时）**：`voice_say("好，我这就去办")` | 用户先听到"开工了"，不是干等 |
| A1 | 干活：查资料 / 改文件 / 跑脚本 | 干完要**自己验收**（看输出、复验文件） |
| A2 | `voice_say(text="…")` 汇报结果 | 返回 `【语音 N.Ns】http://…/seg-xxx.mp3`，记下**文件名**与**时长** |
| A3 | `py.cmd dsh-tools\voice-mark.py --file <文件名> --secs <时长>` | 输出一行 `【语音 N.Ns】http://127.0.0.1:18082/say-file/<文件名>` |
| A4 | 把那一行**单独作为一条消息**发出去 | 前不加字、后不加字、不进代码块、一条只放一个标记 |
| A5 | 另起一条消息写文字复述（长内容） | 不方便听时能看懂 |
| A6 | 结束回合 | 单条语音是回合制：回完就收工，不要等下一句 |

> **和通话一个节奏**：开工先说一句 → 干活 → 验收 → 再汇报（2026-11-05 用户定）。
> 两次 `voice_say` 会排队按顺序播，不需要中间等播放完。

### 不能做

- ❌ 只调 `voice_say` 不跑 `voice-mark.py` —— 工具卡片里**不会**出现播放器
- ❌ 闷头把活干完才出声 —— 中间那段空窗，用户不知道你还在不在（先 A0 应一句）
- ❌ 标记和正文混在同一条消息里 —— 残留超过 24 字，解析器直接放弃
- ❌ 把标记包进 ``` 代码块、或写成 Markdown 链接
- ❌ 一条消息塞两个标记 —— 只认第一个
- ❌ 用户发来语音却用文字回答 —— 必须回语音

## B. 语音通话（持续回合）

### 怎么做

| 步 | 动作 | 说明 |
| --- | --- | --- |
| B1 | 接通后 **3 秒内** `voice_say` 开场白 | 「你好，我是小肥鱼，我听着呢。」客户端 3 秒后才开麦 |
| B2 | 每一轮先 `voice_call_status` | `inCall=false` ＝ 已挂断 → 改文字回复、结束回合 |
| B3 | `voice_wait(timeoutSec=20)` 等新句 | 返回 `lines` / `ended` / `timedOut`；**不要 sleep + 读文件** |
| B4 | **先应一句，再干活** | 要查资料 / 改文件 / 派子代理，先说「好的，我这就去」 |
| B5 | 长内容拆 2–3 条，**连着发完** | 第一组立刻出声、其余组后台合成、客户端排队连播；全部发完再 `voice_wait` |
| B6 | 重活先问 | 「要不要开个子代理去办」→ 派出去 → 我继续陪聊 → 干完报一声并验收 |
| B7 | 回到 B3 | 只有本通 `end` 或 `inCall=false` 才算收工 |

### 不能做

- ❌ 先憋着思考十几秒再出声 —— 空窗比答错更难受
- ❌ 每两步之间夹一次 `voice_wait` —— 会把连续播报切成一段一段
- ❌ 自己数 `voice-inbox.jsonl` 的行数判断挂断 —— 上一通的 `end` 会骗你
- ❌ 念路径、表格、Markdown、括号补充、表情
- ❌ 通话里用文字回复收尾（挂断那一刻除外）
- ❌ 播报期间指望能听见用户说话 —— 麦克风是关的

## C. 红线（犯一条，症状都很明显）

| 红线 | 后果 |
| --- | --- |
| 同一个 TTS 实例并发合成 | 触发 `CUDA error: device-side assert`，整个 18082 进程报废，只能重启 |
| 气泡 `<audio>` 直指 `127.0.0.1:18082` | 被页面 CSP 拦，表现「点了没反应、随后变灰」。必须走同源 `/voice-player/audio?file=` |
| 同时开 `dsh-voice` / `voice-mode` | 两套语音栈抢麦克风 |
| 把 `config.json` 打进发布包 | 那是运行时状态（档位 / 空闲秒），会把你的设置带给对方 |
| 浮层 UI 挂在 `conversation.input.left` 槽位 | 那层祖先带 `transform`，`position:fixed` 会以它为参照系 → 面板错位（2026-11-05 实际踩到）。浮层一律挂 `shell.overlay` |

## D. 排错

> 要**追根因**（不是照表修）：看 `docs/internals.md` —— 机制、先看哪个字段、真实踩坑案例、日志读法都在那儿。

**先看日志再猜**（三个位置）：

| 看什么 | 在哪 |
| --- | --- |
| 通话一问一答 | `…\输出\calls\<sessionId>\voice-inbox.jsonl`（`Get-Content … -Tail 10`） |
| agent 还在不在等 | 同目录 `voice-heartbeat.txt` 的修改时间，3 秒内 = 正在等你说 |
| 服务报错 | `D:\py-tts\logs\tts-service.log`（看到 `CUDA error` 就是实例被打崩，只能重启） |

口诀：**一条请求在日志里出现两次 → 是断句阈值太小，不是 agent 犯傻**；**用户说话时间落在我播报期间 → 半双工吞话，属于设计行为**。

| 症状 | 真因 | 正解 |
| --- | --- | --- |
| 正文有标记但没播放器 | 解析条件不满足 | 查 `<GUI>/voice-player/bubble-report?all=1` 的 `count`；控制台 `window.__voiceDebug()` 看 `parsed / loose / guard` |
| 点播放没反应 / 随后变灰 | 走了 18082 直连 | 改同源代理 |
| 通话被判成「已挂断」 | 读到了上一通的 `end` | 用 `voice_call_status`，别自己数行 |
| 打断后音频又从头念 | 已修（v0.6.0） | 若复现：检查 `client.js` 里 `tick()` 是否还跳过 `suppressed` |
| `voice_say` 报 `18082 -> 500` | TTS 实例被并发打崩 | 串行调用；仍失败就重启 18082 |
| 设置面板位置不对 | 浮层挂错槽位 | 见 C 表最后一条 |

## E. 换机器 / 给别人部署

1. **装**：把本目录链成 `…\.dsh\profiles\<profile>\node_modules\@local\dsh-voice-player`（本机用 junction），或在 profile 里引用本地路径。
2. **依赖**：`D:\py-tts`（18082）、`D:\py-asr`（18080）、ffmpeg —— 路径**写死在 `index.js` / `services.js`**，对方没有同样目录就得改常量，清单见 `README.md §0.5`。
3. **音色**：`D:\py-tts\assets\voice-me.wav`（克隆音色用）。
4. **改完代码必须重启客户端** —— 客户端半边在启动时整包加载，热更不可靠。
5. **验收三条**：悬浮条出现 → 齿轮能开面板且**居中** → 发一句能出播放器。
