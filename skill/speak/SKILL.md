## 0. 一句话流程

**`voice_say` 合成音频 → `voice-mark.py` 生成标记 → 把那一行单独发成一条正文消息。**

## 1. 合成

```
voice_say(text="要说的话")
```

- 一句 ≤600 字；不要一次发多条；
- **它只保证音频生成**，工具卡片**不会**渲染成播放器（2026-11-03 实测 `count:0`）。

## 2. 生成标记

```powershell
py.cmd dsh-tools\voice-mark.py --file <文件名>.mp3 --secs <时长>
```

输出一行：`【语音 N.Ns】http://127.0.0.1:18082/say-file/<文件>`

## 3. 发出去（关键）

**把那一行原样单独作为一条消息发出**：

- 前后不加任何文字（残留 >24 字解析器就放弃）；
- 不用代码块、不写 Markdown 链接；
- 一条消息里只放**一个**标记。

## 4. 文字复述

播放器后面另起一条消息写文字（不方便听时能看）。

## 5. 自检

```powershell
curl.exe -s "<GUI 地址>/voice-player/bubble-report?all=1"
```

`count` ≥ 1 才说明渲染成功；页面 Console 里 `window.__voiceDebug()` 可看每个标记的 `parsed/loose/guard`。

## 失败回退

| 症状 | 处理 |
| --- | --- |
| 不出卡片（工具卡片里） | 正常现象：改用「正文纯标记」发 |
| 不出卡片（正文纯标记） | 查 `count`、`window.__voiceDebug()`；确认前后没加字、没代码块 |
| 播放器点了没反应/变灰 | 音频走同源代理（`/voice-player/audio?file=`），不要直指 18082（CSP 会拦） |
| 用户语音不渲染 | 老 bug：URL 与「转写」间有换行 → 已修正则；仍不行看 `parsed` |
| 合成失败 | 查 18082 `/health`；GPU 档要显存，CPU 档要 INT8（见插件 README） |

## 语音对话的强制规则（2026-10-27 用户定）

**用户用语音说话时，必须用语音回复。** 不是"可以"，是"必须"。

### 时长上限

- 一条语音控制在 **20 秒左右**（中文约 **90–120 字**；实测约 4–5 字/秒）；
- 只把**最要紧的话**放进语音；细节、列表、代码、数据表放文字里；
- 语音里不要念数字表格、路径、Markdown。

### 超长怎么办

- 语音先说结论（一句话），再用文字展开，并说明"没说完的部分在下面"；
- 用户想听更长的，主动提醒可以分条发。

### 说话方式

- 口语，不是朗读稿：短句、少术语、不要"首先其次最后"；
- 不念括号补充、不念表情、不念链接；
- 语音之后另起一条消息写文字。

### 语音消息也要「开工报备 → 收工汇报」（2026-11-05 用户定）

语音消息虽然是回合制，但**要动手的活**照通话的节奏走：

1. **先应一句**：`voice_say("好，我这就去办")` —— 用户先听到你在，不是干等；
2. 干活 + **自己验收**（看输出、复验文件）；
3. **再汇报**：`voice_say` 说干成了什么、有没有坑；
4. 最后用 `voice-mark.py` 给**汇报那条**生成标记，单独成条发出。

两次 `voice_say` 会排队按顺序播，中间**不要**等播放完。纯聊天、不需要动手时，直接一句回复即可。

## 语音通话的三条（2026-11-05 用户定 · 通话中出现「（语音通话已开始）」才适用）

1. **先回应，再动手**：用户说完话，第一句永远是「好的，我这就去…」，然后再调工具、查资料。
   不要先闷头想半分钟再出声——空窗比答错更难受。
2. **实时优先，重活派出去**：通话中不做长时间思考。需要查证、写码、翻大文件的，先问一句
   「要不要开个子代理去办」，用户点头就派出去，自己继续陪聊；子代理干完 → 说一声 → 验收。
3. **长内容连轴合成**：一次把各组 `voice_say` **连着发完**，中间**不夹** `voice_wait`。
   插件本来就是「第一组出声、其余组后台合成、客户端排队连播」，连发才接得上；
   全部发完再 `voice_wait` 等回声。别做成「合成一组 → 等播完 → 再合成下一组」（一段一段断掉）。

补：每轮开头先 `voice_call_status`；被打断就用悬浮条上的「打断」，别自己猜用户听到哪了。
